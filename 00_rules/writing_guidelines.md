# 執筆ガイドライン（トーン＆マナー）

AIエージェントが執筆する際は、以下のガイドラインを遵守してください。

## 1. 文体・トーン
- です・ます調（敬体）を基本とし、一人称は「私」を使用します。
- ターゲット読者：Webエンジニア、技術に興味のある開発者。
- 専門用語は無理に平易にせず、正確な用語を使用してください。
- **事実と意見で文末を書き分けます（最重要）**:
  - 技術仕様・手順など出典のある事実 → 断定調で書く（例: 「イベントを受け取ったら chat.unfurl API を呼び出します」）
  - 著者の考察・感想・推測 → ヘッジ表現で和らげる（例: 「〜のではないかと思います」「〜かもしれません」「〜そうだと感じています」）
- 解説の合間に、読者への口語的な語りかけを適度に挟みます（例: 「いわゆるテストファーストですね」「このあたりは悩みどころですね」）。多用は避け、1セクションに1回程度。
- 重要な用語・機能名・製品名は**太字**で強調します。
- 記事自身を持ち上げる過剰な強調・自己言及表現（例: 「そこが本記事のいちばんの読みどころだと思います」「ここが最大の見どころです」）は書きません（AIっぽさが出るため）。読みどころは宣伝せず、内容そのもので示します。
- 余計な比喩表現を使いません。指す内容が読者にすぐ浮かばないメタファー（例: 「結線」）は避け、そのまま平易に言うか、イメージの湧く言葉（例: 「導線」）を選びます。
- 抽象的な単語でぼかさず、具体的に記述します。総称や曖昧語（例: 「部品」「リソース」「ツール」）で済ませず、指しているものの具体名（例: 「テンプレート」「検証スクリプト」）で書きます。
- 過剰な演出表現を使いません。読者への注目誘導（例: 「3の太字部分に注目してください」）や、「まさに〜」のような大げさな強調表現は書かず、内容をそのまま述べます。

## 2. 記事の構造
- 導入: 背景・きっかけを述べてから、「この記事では、〜について解説したあと、〜を紹介します」の形で記事の内容を予告します。
- 見出し: h2中心。体言止めまたは疑問形（例: 「Slackワークオブジェクトとは？」）。
- 手順は番号リスト、列挙は箇条書きを使います。
- 参照リンクは「参照: [タイトル](URL)」の形式で該当箇所の直後に置きます。
- 締め: 「おわりに」等のまとめ節を必ず設け、著者自身の考察・感想・今後の展望を書き、読者への誘導や挨拶で締めます。

## 3. Zenn特有のMarkdown記法
- 独自のメッセージ記法（要素の強調）を活用してください。
  :::message
  ここにメッセージを記述
  :::
- コードブロックには必ず言語名（例: ````ts````）を指定してください。
