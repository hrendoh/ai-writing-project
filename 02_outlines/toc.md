# 目次と構成案（設計図）

AIエージェントと人間が合意した記事の構成案をここに記述します。

## このファイルの使い方
1. **構成作成フェーズ**: 著者メモを元に構成を作ります。この時点で参照文献は不要です。根拠が必要な記述には `🔍 要出典:` で「どんな根拠があれば書けるか」を書き出します。
2. **調査・キュレーションフェーズ**: `🔍 要出典:` / `🔬 要検証:` の一覧が調査TODOになります（末尾の「調査・検証TODO」表で管理します）。外部文献の抜粋（`REF-xx`）または著者の検証メモ（`NOTE-xx`）で裏付けが取れたら `[REF-xx]` / `[NOTE-xx]` に置き換えます。
3. **構成検証フェーズ**: すべての `🔍 要出典:` / `🔬 要検証:` が解消（`[REF-xx]` / `[NOTE-xx]` 付与・削除・`💬 経験談` と明示のいずれか）されたら執筆に進みます。
4. **決定の履歴**: 一度合意した内容を変更・割愛するときは、行を削除せず打ち消し線＋日付で残します（例: `~~💬 経験談（決定 M/D）: …~~ → **変更（M/D）**: …`）。節ごと割愛する場合も見出しを打ち消し線で残し、割愛理由を書きます。あとから「なぜ書かなかったのか」を追跡できるようにするためです。

### 根拠ステータスの凡例
| 表記 | 意味 |
|------|------|
| `🔍 要出典: <必要な根拠>` | 未調査。どんな根拠があれば書けるかのメモ |
| `🔬 要検証: <必要な検証>` | 著者による検証（`NOTE-xx` 化）が必要なもの |
| `[REF-xx]` | 外部文献の抜粋（`references/REF-xx_*.md`）で裏付け済み |
| `[NOTE-xx]` | 著者自身の検証メモ（`notes/NOTE-xx_*.md`）で裏付け済み |
| `💬 経験談` | 著者の経験・意見として書く（出典不要と人間が合意済み） |
